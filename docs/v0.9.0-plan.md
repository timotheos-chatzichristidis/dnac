# v0.9.0: the plan, and the routine every claim goes through

**Written 2026-09-10**, at the end of the session that found the cue (branch
`nudge`, `docs/origin.md`). The work is split into batches, **one fresh session
per batch**, so each batch starts from written context rather than a long,
tired conversation. No batch is rushed. A batch that finds a problem stops and
records it.

## Decisions already taken (by Timotheos)

1. **v0.9.0 is built around the cue** (`docs/cue.md`, `docs/real-human.md`,
   `docs/remaining.md`).
2. **The light setting is the direction for the default**: on the real human
   pair, level 1 + cue is 2.4x faster than v0.8.0 *and* 3% smaller
   (`docs/speed.md`). This is **conditional on Batch 2**: it has only been
   measured in reference mode (see the risk below).
3. **Originality over competition.** Competitors are measured so the claims are
   honest, not as the goal. Failed ideas are recorded as plainly as the wins
   (`docs/origin.md`).
4. **Nothing is pushed without Timotheos's explicit go-ahead.**

## The risk that must be settled before the default is chosen

Every gain above was measured **with a reference**. dnac's headline claim in
`README.md` is **reference-free**: it beats GeCo3 there by only 0.7%, and level
1 costs +0.375% in that mode. The cue has **never been measured without a
reference**. If it does not help there, "level 1 for everything" would
undercut the codec's strongest existing claim. The default may have to be
chosen per mode. Batch 2 decides it, from data.

## The routine: five passes every claim must survive

Not only "prove it", but also "try to break it" and "try to improve it". A
claim goes into the v0.9.0 README only after all five.

| pass | question | how |
|---|---|---|
| **1. Re-derive** | does the number come back when the recipe is run? | a row in `verify-claims.ps1`: an ANCHOR (the exact sentence) and a VALUE (the recipe, round-tripped). Runs from a clean checkout with data fetched by `scripts/get-data.sh` |
| **2. Break** | can we make the check, or the codec, fail? | every new check watched red (`-SelfTest`); every shipping build flag through `scripts/roundtrip.sh` and `adversarial.ps1`; cross-compiler and floating-point identity (gcc SSE2 / x87 / FMA, clang) re-checked *with the cue*; the negative control (target = reference must leave the cue silent) |
| **3. Compete** | what is the most trivial method on the same input, and the strongest one available? | both in the same table as the claim (METHOD row 7 in bitshape). Losses reported to the same standard |
| **4. Probe for improvement** | is this the best version of itself? | a **pre-registered neighbourhood sweep** of every free parameter, and a **remove-one** test of every component (the 2x2 in `remaining.md` showed a simpler cue can be as good or better). Tune on a **tuning set**, then confirm any change on a **held-out set** nothing was tuned on. A sweep that finds nothing is recorded too |
| **5. Generalise** | at what scale, in what regime, and what breaks above it? | every claim stated with its regime: near-identical bacteria (W3110), diverged (O157), simulated human, real human ×2 chromosomes, reference-free, and at least one regime new to the release |

**Tuning set:** the E. coli targets, `ecoli_ind`, `chr21_ind`, CHM13 chr21.
**Held-out set:** CHM13 chr22 against GRCh38 chr22. It is used only to confirm,
never to choose a parameter. (It was used once already, as the replication in
`remaining.md`, with parameters fixed beforehand. That is allowed.)

Standing rules carried over: the prediction is written and committed before the
run. Timings are paired, back to back, minimum of three (24% noise). A premise
names the command that measured it. Silence is not success. Before any
"beats X", run the most trivial same-input method.

## Batches (one fresh session each)

### Batch 1: instruments first (no codec change)
- Make `scripts/cue/` runnable from the repository: relative paths, and
  `scripts/get-data.sh --cue` fetching CHM13 chr21/chr22 (`CP068257.2`,
  `CP068256.2`) and GRCh38 chr22 (Ensembl 110), plus a script that rebuilds the
  E. coli targets (`make_tumour.py`, seeds 1–3).
- A `verify-claims.ps1` row (anchor + value) for every figure in `nudge.md`,
  `cue*.md`, `real-human.md`, `competitors.md`, `remaining.md`, `speed.md`:
  fast tier for E. coli, slow for chr21/chr22, extern for competitors.
- CI builds `-DDNAC_CUE` and runs `scripts/roundtrip.sh` on it.
- **Exit:** `verify-claims.ps1 -Tier all` green including the new rows, and
  `-SelfTest` red on each new detector.

**Done 2026-09-12 — `docs/batch1.md` has the record. Exit met: all 201 rows
green (`fast` 21, `cue` 90, `slow` 69, `extern` 15, `meta` 6), `-SelfTest` red
on all eight detectors, nothing needing an edit.** 150 rows added (the registry
went 51 → 201), the targets rebuild byte-identically from the
repository in 6 s, `--cue` fetches the human pairs by accession, CI builds the
cue and asserts the flag changes the output, and `-SelfTest` now breaks eight
detectors instead of three. One deviation, stated there: the E. coli rows are a
new `cue` tier rather than part of `fast`, because `fast` is the pre-commit gate
and these rows are an hour. Two things Batch 2 inherits: **run one tier at a
time** (GeCo3 takes 9.2 GB of this machine's 15.7), and the new rows compile
twelve builds, so they need `gcc` (`DNAC_CC`) and `python` (`PYTHON`).

### Batch 2: the regime check (pass 5, before any default is chosen)
- Pre-register, then measure the cue **reference-free**: E. coli, the chr21
  slice, full chr21, the metagenome tier. Level 1 and level 3, with and without
  the cue.
- Cross-compiler and floating-point identity of the cue builds.
- **Exit:** a written, measured decision on the default level per mode.

### Batch 3: probe for improvement (pass 4), at the chosen default
- Pre-registered sweeps: `CUE_L` {2, 3, 4}, `CUE_D` {6, 12, 20}, `CUE_SWITCH`
  {8, 12, 16}, `CUE_MINLEN` {8, 16, 24}, and the room/mixer corners, all at the
  default level.
- **Add-back:** which level-3 parts (other-strand training, tolerant models,
  extra orders, experts) still earn their *time* on top of level 1 + cue.
- Tune on the tuning set. Confirm on chr22 only.
- **Exit:** final parameters, each with its sweep recorded, confirmed held-out.

### Batch 4: integration and format
- The cue becomes a **runtime** feature recorded in the header, so v0.8.0
  archives still decode byte-identically (checked against stored v0.8.0
  streams), with a new magic for new streams. A decoder that predates it
  refuses by name.
- Decide which experiment flags to delete (nudge, `CUE_BACK`) and which to keep
  as diagnostics (`CUE_ROOM`, `CUE_MIXFREE`, `DNAC_PROF`), each for a stated
  reason.
- New round-trip cases: indel-dense, homopolymer-dense, target = reference.
  State files carry the cue reset rule.
- **Exit:** the full routine green on the release candidate.

### Batch 5: claims and release
- README rewritten: results, the cue's origin, and "where this loses" (time,
  the competitors, GeCo3 unverified, the stronger specialists not run). Every
  number with a row.
- `slow` and `extern` tiers green. CITATION 0.9.0. Tag and release only after
  Timotheos says so. `gh` is not installed; the release goes through the
  GitHub REST API (see the dnac memory note on publication).

### After 0.9.0 (not part of it)
- Speed: one frozen, shared copy of the primed reference model across threads,
  so `-j N` works in reference mode (estimate 3–4x on 4 cores). Cheaper mixer
  arithmetic (estimate 15–25%). Both estimates, both to be pre-registered.
- **Ideas inbox:** new cross-domain intuitions from Timotheos go here first,
  and get built and measured as levers before being compared with the
  literature (`docs/origin.md`, "The working rule this leaves").

## Every session, start and end

**Start:** read `CLAUDE.md` ("Where this stands") and this file's status table.
`git status` clean. Build. Run `sh scripts/roundtrip.sh ./dnac` and
`./verify-claims.ps1 -Tier fast`. Green is the baseline. If it is not green,
fixing that *is* the batch.

**End:** every check green, the status table below updated (date, commits,
what is next), committed. Nothing pushed.

**What "every check green" costs, measured 2026-09-12** (one tier at a time —
GeCo3 takes 9.2 GB of this machine's 15.7): `fast` 7 min, `cue` 65 min, `slow`
2 h 52 min, `extern` 19 min, `meta` 30 min -- five hours for all 201 rows. The `cue` and `slow` tiers need a
compiler (`DNAC_CC`, default `gcc`) and `python` (`PYTHON`), because their rows
compile the twelve builds they defend.
