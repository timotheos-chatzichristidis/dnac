# v0.9.0: the plan, and the routine every claim goes through

**Written 2026-09-10**, at the end of the session that found the cue (branch
`nudge`, `docs/origin.md`). The work is split into batches, **one fresh session
per batch**, so each batch starts from written context rather than a long,
tired conversation. No batch is rushed. A batch that finds a problem stops and
records it.

## Decisions already taken (by Timotheos)

1. **v0.9.0 is built around the cue** (`docs/cue.md`, `docs/real-human.md`,
   `docs/remaining.md`).
2. **The light setting is the direction for the default**: on the real human
   pair, level 1 + cue is 2.4x faster than v0.8.0 *and* 3% smaller
   (`docs/speed.md`). This is **conditional on Batch 2**: it has only been
   measured in reference mode (see the risk below).
3. **Originality over competition.** Competitors are measured so the claims are
   honest, not as the goal. Failed ideas are recorded as plainly as the wins
   (`docs/origin.md`).
4. **Nothing is pushed without Timotheos's explicit go-ahead.**

## The risk that was settled in Batch 2 (kept for the record)

Every gain above was measured **with a reference**. dnac's headline claim in
`README.md` is **reference-free**: it beats GeCo3 there by only 0.7%, and level
1 costs +0.375% in that mode. The cue has **never been measured without a
reference**. If it does not help there, "level 1 for everything" would
undercut the codec's strongest existing claim. The default may have to be
chosen per mode. Batch 2 decides it, from data.

**Settled 2026-09-12 (`docs/reference-free.md`).** Reference-free the cue is a
gain everywhere at level 3 and the largest is 0.045% — it does not hurt the
headline, so it ships always on. But it does **not** carry level 1 there: level
1 + cue costs +0.53% against level 3 on chr21 and +1.89% on the metagenome, so
"level 1 for everything" is off. **The default is per mode: level 3 without a
reference, level 1 + cue with one.**

## The routine: five passes every claim must survive

Not only "prove it", but also "try to break it" and "try to improve it". A
claim goes into the v0.9.0 README only after all five.

| pass | question | how |
|---|---|---|
| **1. Re-derive** | does the number come back when the recipe is run? | a row in `verify-claims.ps1`: an ANCHOR (the exact sentence) and a VALUE (the recipe, round-tripped). Runs from a clean checkout with data fetched by `scripts/get-data.sh` |
| **2. Break** | can we make the check, or the codec, fail? | every new check watched red (`-SelfTest`); every shipping build flag through `scripts/roundtrip.sh` and `adversarial.ps1`; cross-compiler and floating-point identity (gcc SSE2 / x87 / FMA, clang) re-checked *with the cue*; the negative control (target = reference must leave the cue silent) |
| **3. Compete** | what is the most trivial method on the same input, and the strongest one available? | both in the same table as the claim (METHOD row 7 in bitshape). Losses reported to the same standard |
| **4. Probe for improvement** | is this the best version of itself? | a **pre-registered neighbourhood sweep** of every free parameter, and a **remove-one** test of every component (the 2x2 in `remaining.md` showed a simpler cue can be as good or better). Tune on a **tuning set**, then confirm any change on a **held-out set** nothing was tuned on. A sweep that finds nothing is recorded too |
| **5. Generalise** | at what scale, in what regime, and what breaks above it? | every claim stated with its regime: near-identical bacteria (W3110), diverged (O157), simulated human, real human ×2 chromosomes, reference-free, and at least one regime new to the release |

**Tuning set:** the E. coli targets, `ecoli_ind`, `chr21_ind`, CHM13 chr21.
**Held-out set:** CHM13 chr22 against GRCh38 chr22. It is used only to confirm,
never to choose a parameter. (It was used once already, as the replication in
`remaining.md`, with parameters fixed beforehand. That is allowed.)

Standing rules carried over: the prediction is written and committed before the
run. Timings are paired, back to back, minimum of three (24% noise). A premise
names the command that measured it. Silence is not success. Before any
"beats X", run the most trivial same-input method.

## Batches (one fresh session each)

### Batch 1: instruments first (no codec change)
- Make `scripts/cue/` runnable from the repository: relative paths, and
  `scripts/get-data.sh --cue` fetching CHM13 chr21/chr22 (`CP068257.2`,
  `CP068256.2`) and GRCh38 chr22 (Ensembl 110), plus a script that rebuilds the
  E. coli targets (`make_tumour.py`, seeds 1–3).
- A `verify-claims.ps1` row (anchor + value) for every figure in `nudge.md`,
  `cue*.md`, `real-human.md`, `competitors.md`, `remaining.md`, `speed.md`:
  fast tier for E. coli, slow for chr21/chr22, extern for competitors.
- CI builds `-DDNAC_CUE` and runs `scripts/roundtrip.sh` on it.
- **Exit:** `verify-claims.ps1 -Tier all` green including the new rows, and
  `-SelfTest` red on each new detector.

**Done 2026-09-12 — `docs/batch1.md` has the record. Exit met: all 201 rows
green (`fast` 21, `cue` 90, `slow` 69, `extern` 15, `meta` 6), `-SelfTest` red
on all eight detectors, nothing needing an edit.** 150 rows added (the registry
went 51 → 201), the targets rebuild byte-identically from the
repository in 6 s, `--cue` fetches the human pairs by accession, CI builds the
cue and asserts the flag changes the output, and `-SelfTest` now breaks eight
detectors instead of three. One deviation, stated there: the E. coli rows are a
new `cue` tier rather than part of `fast`, because `fast` is the pre-commit gate
and these rows are an hour. Two things Batch 2 inherits: **run one tier at a
time** (GeCo3 takes 9.2 GB of this machine's 15.7), and the new rows compile
twelve builds, so they need `gcc` (`DNAC_CC`) and `python` (`PYTHON`).

### Batch 2: the regime check (pass 5, before any default is chosen)
- Pre-register, then measure the cue **reference-free**: E. coli, the chr21
  slice, full chr21, the metagenome tier. Level 1 and level 3, with and without
  the cue.
- Cross-compiler and floating-point identity of the cue builds.
- **Exit:** a written, measured decision on the default level per mode.

**Done 2026-09-12 — `docs/reference-free.md`, registered in `ddee2c4`.**
Six of seven predictions held; P5 failed and inverted (the cue's gain is
*smaller* at level 1 without a reference, where with one it was larger). The
cue is a gain at level 3 on all four datasets, largest 0.045%, so it ships
always on. **Decision: level 3 reference-free, level 1 + cue in reference
mode** — level 1 + cue costs +0.53% on chr21 and +1.89% on the metagenome
against level 3, so "level 1 for everything" is out. Float identity holds
across six builds (`-O2`, `-O3`, x87, SSE2, FMA on/off): byte-identical
archives, all 72 cross-decodes clean. clang is not on this machine, so the
cross-compiler half was added to CI instead. 30 rows added (registry 201 →
231), all green.

### Batch 3: probe for improvement (pass 4), at the chosen defaults

**What Batch 2 hands over, so this is not re-derived:** there are now **two**
defaults, not one — level 3 reference-free, level 1 + cue with a reference
(`docs/reference-free.md`). Sweep at **level 1 in reference mode**: that is
where the cue does its work (−5.97% on a real pair against −0.045% plain), so
it is where a parameter can be seen to matter. Re-check the winner at level 3
in both modes before adopting it, since a setting tuned where the mechanism is
loud can cost something where it is quiet.

- Pre-registered sweeps: `CUE_L` {2, 3, 4}, `CUE_D` {6, 12, 20}, `CUE_SWITCH`
  {8, 12, 16}, `CUE_MINLEN` {8, 16, 24}, and the room/mixer corners.
- **Add-back:** which level-3 parts (other-strand training, tolerant models,
  extra orders, experts) still earn their *time* on top of level 1 + cue.
- **One question Batch 2 raised and could not answer:** reference-free, the
  cue's gain *shrinks* at level 1, the opposite of what it does with a
  reference. The hypothesis on record is the mixer's context — level 1 has two
  experts, level 3 has four, and a rare input needs the finer context most. The
  test is a level-1 build with four experts, which is an add-back run, and it
  would also say whether reference-free deserves its own level.
- Tune on the tuning set (the E. coli targets, `ecoli_ind`, `chr21_ind`, CHM13
  chr21). Confirm on chr22 only.
- **Exit:** final parameters, each with its sweep recorded, confirmed held-out.
- Budget note: `-Tier all` is five hours, so run `-Only 'cue-*'`-style
  selections while iterating and keep the full registry for the end.

**Done 2026-09-14 — `docs/batch3.md`, registered in `5700d4e`.** One parameter
was adopted and nothing else: **`CUE_MINLEN` 16 → 4**, which is −0.898% on the
real human pair at level 1 in reference mode, −0.839% on the held-out chr22,
a gain in plain mode at both levels (reference-free the cue's level-3 gain on
chr21 goes 0.045% → 0.106%), and **+0.1% time**. **The add-back is a clean no:**
tolerant models −1.225% for +29.0% time, other-strand −0.554% for +13.9%, four
experts −0.523% for +21.1%, the master order set −0.458% for +15.8% — D2 asked
for ≥ 1.0% at ≤ 20% or ≥ 0.5% at ≤ 10%, and none of them clears it. Batch 2's P5
hypothesis (the mixer's context) is **retired**: four experts leave the cue's
reference-free gain on chr21 unchanged to four decimals. Five predictions held,
four failed, three part-held, one unanswered; the two failures that mattered
(P2, P5) were both "this parameter is inert". Two instrument findings are in
that document: the screen's per-event ranking does **not** predict the human
pair (the pre-registered staging rule would have discarded the winner, and the
disclosed widening is what found it), and a check behind a pipe under `set -e`
cannot go red. 50 rows added in a new `cue3` tier (registry 231 → 281).

**What Batch 4 must plan around, stated here so it is not discovered late:**
every published figure on this branch was measured at `CUE_MINLEN=16`, so
`CUE_MINLEN=4` is adopted **by decision, not yet as the default in `dnac.c`**.
Flipping it makes the per-event costs, the −5.97% / −18.27% window splits, the
chr22 replication, the competitor table and `docs/speed.md` stale at once. **The
flip and the re-measurement are one change**, or `verify-claims.ps1` goes red on
a hundred rows — correctly.

### Batch 4: integration and format

**What Batch 3 hands over, so this is not re-derived (`docs/batch3.md`):**

1. **`CUE_MINLEN` 16 → 4 is adopted by decision and is NOT yet the default in
   `dnac.c`.** Flipping it is the first job — and the flip and the
   re-measurement are **one change**, because every published figure on this
   branch was measured at 16.
2. **Do not overwrite the old documents' numbers.** `docs/cue.md`,
   `cue-room.md`, `cue-back.md`, `real-human.md`, `remaining.md`, `speed.md` and
   `competitors.md` are records of pre-registered experiments run at
   `CUE_MINLEN=16`. Editing their figures to match a new build would destroy the
   record the whole routine exists to protect. They stay as they are, with one
   sentence added to each saying which parameter set they were measured at.
3. **The mechanical consequence:** once the default is 4, `-DDNAC_CUE` alone no
   longer reproduces those numbers, so **the `cue` label must become explicit**
   (`-DDNAC_CUE -DCUE_MINLEN=16`) in both `scripts/cue/common.sh` and `CueDefs`,
   and a **new label for the shipping default** (`-DDNAC_CUE`, i.e. 4) carries
   the release measurements. The self-test compares those two tables, so they
   cannot drift apart silently. Expect ~100 rows to need exactly this and
   nothing else; any row that needs more is telling you something.
4. **The release figures must be re-measured at 4**: the per-event costs, the
   −5.97% / −18.27% window splits, the chr22 replication, `docs/speed.md`'s
   level table and the competitor table. That is Batch 5's input, so produce it
   here.
5. **The negative control in pass 2 is wrong as phrased.** Target = reference
   does **not** leave the cue silent: it fires (a master match still misses on
   an identical copy) and the file is 0.7% smaller. Test that it **costs
   nothing and stays lossless**, not that it produces identical bytes.
6. **No new level number is needed.** The add-back said no to all four level-3
   parts, so level 1 + cue stays exactly the model set it is.
7. **Flags:** the four `L1_*` knobs stay as diagnostics (they are how the
   add-back question gets asked again if anyone proposes a new level), and the
   sweep labels in `common.sh` stay because the `cue3` rows compile them.
8. **Quote the paired speed ratio, 2.12x**, not `docs/speed.md`'s 2.4x, which
   came from two single runs in different minutes. Same machine, same rounds:
   202.07 s against 95.39 s.

- **The per-mode default from Batch 2 becomes what the CLI picks**: level 3
  without a reference, level 1 with one (`docs/reference-free.md`). The level
  already travels in the header, so this is a change to the default, not to the
  format — but it changes what `dnac cr` writes when the user says nothing, so
  it needs its own round-trip cases and a line in the README.
- The cue becomes a **runtime** feature recorded in the header, so v0.8.0
  archives still decode byte-identically (checked against stored v0.8.0
  streams), with a new magic for new streams. A decoder that predates it
  refuses by name.
- Decide which experiment flags to delete (nudge, `CUE_BACK`) and which to keep
  as diagnostics (`CUE_ROOM`, `CUE_MIXFREE`, `DNAC_PROF`), each for a stated
  reason.
- New round-trip cases: indel-dense, homopolymer-dense, target = reference.
  State files carry the cue reset rule.
- **Exit:** the full routine green on the release candidate.

**What Batch 4 hands over to Batch 5, so none of it is re-derived or missed
(`docs/batch4.md`):**

1. **Three record claims do not carry to the release, and the README must not
   quote them as release claims.** "Exactly 0 on sequence one person lacks" is
   now a small *gain* there (−0.23% to −0.34%), because `CUE_MINLEN=4` lets the
   cue act after short matches. "1.6x ahead of the best competitor" is 1.62x at
   level 3 but **1.57x at level 1**, the reference-mode default. "Level 1 + cue
   3% smaller than v0.8.0" is **−4.02%** now (563,031 against 586,615).
2. **The default loses on the tightest bacterial pair.** W3110 against MG1655:
   the level-1 default is **+9.84%** against v0.8.0's level-3 default (2,121 B
   against 1,931 B), O157 +0.05%. The cue gains at both levels; level 1 costs
   more than the cue wins back on a 2 kB file. Batch 2 chose the per-mode
   default on human and metagenome data. Batch 5 either states this in "Where
   this loses" or re-opens the reference-mode default — measured, not argued.
3. **Two CI checks have never run**, because nothing is pushed: the stored
   v0.8.0 streams (written on Windows x86-64) decoding on **macOS arm64**, where
   clang's floating-point contraction could differ, and the new "families
   never mix" step. A red macOS job there would be a real cross-platform
   finding, not a flaky test.
4. **The records are pinned to `4932ffe`.** Every old label compiles that source;
   only `rel`, `v08` and `exp` compile the working tree. A clean checkout needs
   the git history for this (CI's `fetch-depth: 0` does it).
5. **The README still describes v0.8.0** and its rows run the `v08` build on
   purpose. Rewriting it is Batch 5's job, and each release figure it quotes
   already has a `b4` row to anchor to.

## Every session, start and end

**Start:** read `CLAUDE.md` ("Where this stands") and this file's status table.
`git status` clean. Build. Run `sh scripts/roundtrip.sh ./dnac` and
`./verify-claims.ps1 -Tier fast`. Green is the baseline. If it is not green,
fixing that *is* the batch.

**End:** every check green, the status table below updated (date, commits,
what is next), committed. Nothing pushed.

**What "every check green" costs, measured 2026-09-12** (one tier at a time —
GeCo3 takes 9.2 GB of this machine's 15.7): `fast` 7 min, `cue` 65 min, `slow`
2 h 52 min, `extern` 19 min, `meta` 30 min -- five hours for all 201 rows, plus
Batch 3's `cue3` tier (~90 min, 50 rows). The `cue` and `slow` tiers need a
compiler (`DNAC_CC`, default `gcc`) and `python` (`PYTHON`), because their rows
compile the twelve builds they defend.
